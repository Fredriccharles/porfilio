01About

I'm a front-end developer finishing a BSIT degree and building real, working software on the side rather than stopping at tutorials. My current project, a multi-widget personal dashboard, forced me to actually solve problems I hadn't faced before — unreliable API keys, inconsistent response data, and real-time sync through Supabase, a database layer I was new to going in. I treat unfamiliar territory as something to work through, not avoid: I research fast, lean on AI-assisted debugging when it gets me to a working fix faster, and then take the time to understand and test that fix myself so I actually own the solution.

I care about three things in how I work. Creativity, because the obvious layout is rarely the right one. Resourcefulness, because every project hits a wall — a key that won't authenticate, a query that returns the wrong shape of data, a layout that breaks at one viewport — and the job is finding a way through it, not waiting for someone else to. And reliability, because the most useful person on a team is the one whose updates and estimates you don't have to double-check.

widget-dashboard/

Widget Dashboard

A personal home-screen app combining a live weather widget, a news feed widget, a freeform whiteboard, and a vision-board canvas — with shared boards so a friend can collaborate on the same whiteboard or vision board in real time.

The weather and news integrations were the first real wall: API keys that silently failed and responses that didn't always come back in the shape I expected. Supabase's real-time layer was the second — databases weren't an area I'd worked in much before, so getting shared boards to sync correctly meant learning that side of the stack as I built. I used AI-assisted research to move through documentation and error messages faster, then verified, tested, and adjusted each fix myself until the integrations and the sync held up reliably.

  • Supabase Realtime
  • Canvas
